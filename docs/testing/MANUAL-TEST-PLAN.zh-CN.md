# Brief 完整功能测试指南

本测试包用于验证 Brief 是否能帮助企业用户把素材快速整理为可核对、可分享的项目报告。全部数据与人名均为虚构；不是实际业务结论。版本基线为 2026-09-26 的当前实现。

先解压 ZIP。`valid` 是正常素材，`invalid` 是故意损坏或不满足约束的素材，`reference` 是完整报告及版式示例。不要将所有文件一起上传。每条用例结束后取消弹窗或新建报告，以免素材互相影响。备份文件现在可以直接拖入普通上传区：系统识别为报告后，预览并选择 Open as new report；也可以通过 Settings → Restore backup as separate copies 恢复。两者都建立独立副本。

本指南覆盖当前用户可见功能及主要错误路径，并不代表所有浏览器、所有文件结构均已验证。AI、操作系统分享、邮件客户端和打印需要在真实目标环境中复验；自动化模拟成功不代表第三方软件已实际接收。

## 十分钟验收路径

1. **完整成品**：在 Settings 中恢复 `reference/01-retrospective-backup.json`，关闭设置，到报告列表打开恢复的报告。应有 10 张卡片、2 名人员、1 个来源，版式为 Project retrospective。
2. **版式**：点击 Preview layout。检查标题、数据与指标、决策、风险、两行行动表、核心共识。将 Weekly update 与 Project retrospective 来回切换，卡片内容与数量不能变化。刷新后应保留最后选择。
3. **真实输入**：新建报告，上传 `valid/04-project-data.json`。选 completed、team、date，点击 Find patterns。结果应包含 8/10 条可用记录、均值 45、中位数 35、IT 均值 30、Operations 均值 60，以及图表。
4. **错误处理**：取消导入，上传 `invalid/02-broken-line-3.jsonl`。错误必须指出第 3 行，不能先导入前两行。
5. **Word 与 PDF**：分别上传 `valid/17-project-brief.docx`、`valid/18-selectable-text.pdf`；检查提取预览，确认后才加入素材。上传 `invalid/20-image-only.pdf` 应提示先 OCR。
6. **风险复核**：用 `valid/13-risk-notes.txt` 建立报告，点击 Review project risks。查看证据并手动勾选一条加入；Undo 能撤销，不得自动添加全部风险。
7. **交付**：在完整示例中 Share → Download HTML，打开后应居中；Print / Save as PDF 检查图表和行动表；Share as image 查看 PNG；Put cards into slides 下载 PPTX。

## 测试记录与判定标准

建议每次记录：用例 ID、环境和浏览器版本、实际结果、通过/失败/未测、截图或导出文件、缺陷描述。文末提供 CSV 模板。

阻断级缺陷：数据丢失、错误统计、未确认就新增报告内容、导入脚本执行、现有报告被错误覆盖。严重缺陷：导入卡住、无法恢复备份、主要按钮不可用、导出内容被截断。一般缺陷：间距、非关键文案、可恢复的小交互问题。不得把功能未实现标记为通过。

每条失败用例都应检查：原报告数量、卡片数量、原始素材是否未被意外改变；错误是否可理解；能否立即上传下一个正常文件。

## 参考模板的设计取舍

保留参考图的“证据 → 决策与风险 → 行动 → 共识”阅读顺序。采用系统字体、白色内容区、白底内容块、细分隔线与少量分区色条，减少大面积彩色底纹。标题与文字承担层级，颜色只作辅助；短卡并排，图表跨行，手机自动单列。

当前分区映射：Progress → 数据与指标；Needs a decision → 待对齐决策；Needs discussion → 协作与风险；Next steps → 行动计划；Key takeaways → 核心共识。最后一个分区也可在普通周报中使用。不会把“成功指标有效性”当成机器自动确认的事实。

行动表使用真实已有的负责人、正文和期限。当前没有任务完成状态，所以不自动生成“进行中/已完成”。含图表、图片或相关链接的行动卡保留完整卡片，避免表格化导致内容丢失。预览与HTML/PDF共用版式；邮件客户端可能降级，PNG与PPTX采用各自的可读布局。

`reference/02-retrospective-preview.html` 可直接打开看完整成品；要编辑请恢复旁边的 JSON 备份。不要把该 HTML 再上传当成备份恢复。

## 覆盖边界与后续优先级

当前不支持扫描件OCR、老.doc、任意.xlsx、PDF原样排版、DOCX嵌入图片还原、任意HTML脚本运行、自动推断指标业务含义、真实任务状态同步、自动发送邮件或会议邀请。遇到这些要求时，应明确说明边界，而不是生成貌似完整的结果。

优先保障：数字与源文件一致；零与缺失值区分；取消/失败不污染报告；可在少量步骤内到达可分享成品。建议记录从打开工具到首次下载合格报告的时间，以及用户修改卡片数、是否需要帮助。可以设定“首次用户10分钟内完成测试示例”的目标，但这只是待验证目标，不是已经测得的产品指标。
